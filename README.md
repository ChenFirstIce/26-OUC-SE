# 阿尔茨海默病认知评估与量表管理系统

本项目是中国海洋大学软件工程实践课程项目，目标是构建一套面向受检者与医生的认知评估系统，完成受检者档案管理、量表填写、草稿保存、规则计分、结果查询和基础统计等流程。

> 项目当前处于第一阶段 MVP 开发阶段。患者端已提供 C/B 阶段四项独立演示功能，其余应用目录仍待团队初始化。

## 项目目标

第一阶段计划打通以下核心闭环：

```text
医生创建受检者与评估任务
          ↓
生成二维码链接和 8 位备用评估码
          ↓
受检者使用手机完成量表
          ↓
服务端保存原始回答并自动计分
          ↓
医生查看结构化报告和基础统计
```

MVP 计划优先实现：

- 受检者基础档案管理；
- SCD-Q9、GDS-15 两张量表；
- 二维码链接与备用评估码；
- 答题草稿自动保存与恢复；
- 服务端规则计分；
- 逐题回答、总分及基础统计展示；
- 单一医生演示账号与编号化虚拟数据。

## 系统架构

当前保留两种候选方案：

1. 全 Web：患者移动端 Web + 医生管理 Web + 统一后端 API + 数据库；
2. 微信小程序：患者微信小程序 + 医生管理 Web + 统一后端 API + 数据库。

推荐的工程边界如下：

```text
patient-web/   患者移动端 Web
admin-web/     医生桌面端 Web
server/        统一后端服务
contracts/     API 文档、公共类型及错误码
docs/          需求材料、项目计划和分析文档
src/           预留源码目录
```

前后端通过统一 JSON API 联调。计分以服务端结果为准，数据库同时保存原始答案，以便评分规则调整后重新计算。

## 核心功能

### 患者端

- 扫描二维码或输入备用码进入评估；
- 查看量表说明及答题进度；
- 分步骤填写量表并自动保存草稿；
- 刷新或退出后恢复未完成内容；
- 提交前检查漏答项；
- 提交后锁定任务并显示中性完成提示。

患者端以移动优先和中老年用户友好为设计原则，不展示疾病诊断结论。

### 医生端

- 医生登录；
- 创建、查看受检者档案；
- 创建评估并生成访问链接、二维码及备用码；
- 查看评估状态和历史记录；
- 查看逐题答案与量表得分；
- 查看受检者数、已完成评估数及量表平均分。

### 后端

- 医生身份认证；
- 受检者、评估、回答和计分结果管理；
- 安全令牌与备用评估码生成；
- 草稿的幂等保存；
- 完整性校验和服务端规则计分；
- 在同一事务中完成答案保存、计分、结果保存和状态更新。

## 量表范围

项目按实现方式将量表与任务分为三类：

- A 类：受检者可直接填写的结构化量表，第一阶段优先实现；
- B 类：可由计时、语音、图像或交互程序辅助的标准化任务；
- C 类：可由大语言模型辅助追问或分析开放回答的访谈任务。

第一阶段只实现已确认范围内的结构化量表和基础功能。正式题目、评分规则及解释必须以仓库中的原始量表和操作说明为依据，不自行编造医学内容。

## 获取项目

使用 SSH：

```bash
git clone git@github.com:ChenFirstIce/26-OUC-SE.git
cd 26-OUC-SE
```

也可以使用 HTTPS：

```bash
git clone https://github.com/ChenFirstIce/26-OUC-SE.git
cd 26-OUC-SE
```

患者端演示已可运行：

```bash
cd patient-web
npm install
npm run dev
```

详细说明请参阅 [`patient-web/README.md`](patient-web/README.md)。医生端、后端、数据库初始化和生产部署命令将在对应工程落地后补充。

## 协作约定

每位成员在独立分支上开发，并通过合并请求集成到 `main`：

```bash
# 创建个人分支
git switch -c <name-or-feature>

# 同步主分支
git fetch origin
git merge origin/main
```

建议提交信息简洁说明变更内容，提交前完成对应模块的构建和测试，并避免提交真实患者隐私数据。

## 数据与医疗声明

- 本项目用于课程实践和原型演示，不构成医疗器械或临床诊断工具；
- 演示与测试仅使用编号化虚拟数据；
- 不在仓库、日志或截图中保存真实姓名、联系方式、病历等敏感信息；
- 评估结果只提供中性提示，诊断与临床解释应由具备资质的专业人员完成。
