## 重复实现的取舍

- `dl/backend` → `server`，`dl/frontend` → `admin-web`。Vue 患者入口仍为 `/p/fill/:token`，与医生端共用一个构建产物；不拆分第二套任务身份。
- `yjj` 作为已被 dl 整合的来源保留溯源及回归测试，不覆盖 dl 的迁移和版本治理。
- `lfy` 的 `AssessmentRenderer` 逐题导航、答题进度和 `HistoryPage` 完成记录交互改写到 Vue；`mockRepository`、本地身份和本地权威计分不进入正式系统。原 React 原型仍能从固定提交取回。
- `lfy` 的 SCD 布尔答案映射为服务端 `yes/no`；三道频率题保留 `often/sometimes/never` 与 1/0.5/0 分。GDS 反向题为 1、5、7、11、13；ESS 按各题 0–3 分；利手累计方式相同。正式逻辑选择 dl，避免两处规则漂移。
- `lfy` 的原始资料及图片保存在 `docs/references/lfy/`。原材料中的阶段状态说明作为历史参考保留，不作为当前运行说明。
- `main` 的四项演示交互已改写到 `admin-web`，通过正式患者任务入口运行；原 React 目录保留作来源参考。React STT 已使用 `patient-web/stt_sequences_with_coordinates.json` 与 `patient-web/stt_age_thresholds.json` 呈现完整 STT-A/B 节点和年龄阈值，Boston 图像与 SCD 对话仍明确标注为占位内容。

## 明确缺口

1. 原需求提出 8 位备用码；当前正式实现为链接加 6 位码，没有仅输入备用码定位任务的入口。本轮保留现有契约。
2. 正式量表目录默认需要管理员预览、导入和发布；初次启动已发布的是两张明确标注为 DEMO 的问卷，不能混称正式 SCD/GDS。
3. DeepSeek 接入仅用于候选追问/候选分析，且支持本地降级；无语音识别或正式 Boston 图片素材。STT 来源参考端已补入 PDF 坐标缩放和年龄阈值，但当前 C/B 仍为 DEMO/辅助任务流程，不可视为经医学认证的正式施测。
4. MMSE 等分域录入与 CDR 等人工复核并非完整自动施测。需受训人员参与的量表不能仅凭可派发页面算作临床完成。
5. 草稿冲突和幂等的验证覆盖顺序请求；没有进行数据库并发压力、渗透或真实移动设备网络测试。
6. 服务器量表定义与现有分支计分进行了代码级核对和边界测试；本轮未进行医学规则、授权或诊断有效性的外部认证。
