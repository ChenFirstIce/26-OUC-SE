# 患者端项目规格说明

## 1. 项目定位

课程项目整体存在医生/管理端与患者端两条系统线。患者端当前**独立开发、独立演示**，不等待医生端的患者管理和任务派发完成。

患者端增加一个极简 Admin/Test Mode，用本地 mock 数据模拟“任务已由医生派发”。后续真实联调时，将 Admin/Test Mode 的创建任务动作替换为医生端/后端生成 assignment 即可。

## 2. 端到端业务闭环

```text
管理员测试模式
  -> 选择演示患者
  -> 选择一个或多个评估
  -> 创建 assignment
  -> 患者任务中心出现任务
  -> 患者开始/继续评估
  -> 自动保存草稿
  -> 完成并提交
  -> 生成结构化 submission
  -> 历史记录可查看
```

## 3. 三类评估能力

### A. 结构化量表

用配置驱动的 Assessment Engine 渲染，适合是/否、单选、多选、等级、数值、日期、文本等。

首批：SCD-Q9、GDS-15、ESS、爱丁堡利手量表。

### B. 非 LLM 标准化交互

独立 Task Component，记录过程指标。

首批：Boston 命名、STT 形状连线。

### C. LLM 辅助

患者前端只负责输入、对话、loading、结果确认和 API 协议；模型提示词和最终医学判断不放前端。

首批：SCD 结构化访谈、MoCA-B 开放回答子任务。

## 4. 数据结构原则

不要只保存总分。Submission 应保留：

- 原始回答 answers
- 每题初步 score（若适用）
- 总分 rawScore
- 开始/结束时间
- 总耗时
- 特殊任务 errorCount / hintCount / sequence 等
- AI 任务原始对话/开放回答与候选分析（内部数据）

前端 score 仅作为 provisional score；未来后端应重新校验。

## 5. 页面设计原则

- 面向中老年用户，手机优先
- 大字号、大触控区域、低信息密度
- 普通评估一屏一题
- 进度明确
- 避免复杂动画
- 患者端不直接输出“诊断”
- “完成”“建议进一步专业评估”等中性表达优先

## 6. 管理员模式边界

允许：

- 创建/批量创建 assignment
- 清除/重置 demo 数据
- 查看提交 JSON
- 快速切换任务状态便于演示

不做：

- 复杂医生工作台
- 医嘱、处方、病历系统
- 医院统计大屏
- 医生权限体系

## 7. 首版验收

最低可演示闭环：

```text
/admin -> 派发 SCD-Q9/GDS/ESS
/home -> 看见 3 个待完成任务
/assessment/... -> 正常答题并自动保存
/complete -> 提交成功
/history -> 可查看已完成与提交 JSON 摘要
```

随后补 Boston/STT 和 AI mock。
